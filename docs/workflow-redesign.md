# 2026-11-04 웹 작업 흐름 개편

초급·중급 모두 목적 → 자료·컨텍스트 → 추출·구조화 → 근거 조회·RAG → 작성·수정 → 평가·오류 진단 → 저장·재사용의 흐름을 따른다. 각 단계에서 AI가 줄이는 처리, 사람이 결정할 사항, 입력, 다음 단계에 넘길 결과, 통과 기준을 함께 제시한다. 단순 요약이나 짧은 문구 작성만으로 활용 효과를 주장하지 않는다.

## 반별 구성

각 과정은 독립 180분이다. AI 기본·전체 흐름 20분, 적용 사례 35분, 휴식 10분, 설명·시연 5분, 적용 사례 40분, 휴식 10분, 설명·시연 5분, 적용 사례 45분, 정리 10분으로 구성한다. 7단계는 참고·진행 구조이며 7개의 별도 시간 블록을 추가한 것이 아니다.

| 과정 | 사례 ID | 새 작업 | 주 자료와 활용 이유 |
|---|---|---|---|
| 초급 | meeting | 목적·자료 설정과 정보 구조화 | 북구 업무계획 17쪽의 표현을 선정 기준·분류·근거 위치가 있는 공통 표로 정리 |
| 초급 | adapt | 확인한 정보로 문서 작성·수정 | 같은 업무계획과 검토한 표를 내부 메모·공유 문서로 재구성하며 사실 유지 |
| 초급 | email | 오류 진단과 작업 기록 보존 | 업무계획 초안의 오류 원인을 나누고 해당 단계 수정·기록·백업 |
| 중급 | document | 자료 역할 설계와 RAG 조회 준비 | 편람 383쪽·규정·시행규칙·공고에서 형식 기준과 사업 사실의 역할·버전 구분 |
| 중급 | sources | RAG 근거 조회와 검토 문서 작성 | 기본 5개 소스의 전체/관련 범위 비교, 주장·인용·원문 대조, 근거 카드·문서 작성 |
| 중급 | template | 컨텍스트 전환과 재사용 흐름 설계 | 공고에서 업무계획으로 전환하고 이전 사실 혼입 검사, 지시·자료·도구·상태·검토 보존 |

공고의 상충 금액은 짧은 문서를 AI에 맡길 이유를 과장하는 사례 대신 오류 진단·미결 보존·확인 질문 사례로 사용한다. 다른 업무로 전환하는 혼입 시험과 동일 유형의 다른 자료로 절차를 재적용하는 반복성 시험을 구분한다.

## 시각 자료와 조작

- 7단계 흐름과 오류 발생 후 복귀 경로.
- 현재 수정 / 새 대화 인수인계 / 다른 업무 전환의 컨텍스트 트리.
- 형식·금액·일정 질문에 따른 소스 선택 트리. 이 조작은 교육용 설계 예시이며 외부 NotebookLM을 제어하지 않는다.
- RAG 등록·변환 / 질문·소스 범위 / 관련 구절 조회 / 근거로 생성 / 인용·원문 대조의 5단계 탐색.
- 지시·자료·도구·상태·검토를 연결하는 하네스 도식. 수업은 사람이 운영하는 절차이며 자동 에이전트를 구현한 것으로 표시하지 않는다.
- 오류 유형 6개와 되돌아갈 단계. 원인 미확인도 허용한다.
- 준비·실행·검토·반복 건수의 총작업시간 비교. 사용자가 실측값을 넣기 전에는 절감 시간을 표시하지 않는다.

개념·도구 참고서는 별도 `#reference` 경로에 15개 주제를 양 과정 모두 제공한다. AI 기본, 요청 구성, 무료·유료 선택, 파일, 컨텍스트, RAG, 검증, 보안, 인수인계 등의 깊이 있는 설명은 유지한다. 기존 `#concepts?...&topic=...` 주소는 관련 작업 흐름 단계로 연결한다.

## 데이터와 버전

- 웹 편성: `src/flow-curriculum.js`; 단계 원리·사례·근거: `src/flow-content.js`.
- 웹 사례·단계별 안내: `src/flow-lessons.js`; UI: `src/WorkflowCourse.jsx`, `src/workflow.css`.
- 교재용 원본 `content/curriculum.json`, `src/content.js`, `src/walkthroughs.js`, `src/course-foundations.js`는 동결한다. 웹은 `src/web-copy.js`의 표시 계층에서 새 사례를 적용한다.
- 기존 PDF v2.1(79쪽)은 이번 개편을 포함하지 않는다. 다운로드 안내에 웹과 교재의 차이를 명시한다. PDF·원문·캡처 파일 및 출처 목록은 유지한다.
- 기존 캡처는 2026-10-14 실행 기록이다. 새 요청을 실행한 증거로 표시하지 않는다. 특히 초급 문서 작성의 공고 캡처는 업무계획의 새 결과가 아니라 사실 유지·재구성의 비교 사례임을 명시한다.
- 저장 키 `ulsan-ai-workroom-v1`, 기존 여섯 사례 ID와 작성 글은 유지한다. 기존 `completed`/`checks`는 보존하고 새 기준은 선택 필드 `workflow: {revision:'flow-2026-11-04', completed, checks}`에 기록한다. 이전 완료 표시를 바뀐 과제의 검토 완료로 자동 변환하지 않는다. JSON 백업은 두 기록을 함께 포함한다.

## 출처와 검증 경계

개념은 Google의 LLM/NotebookLM/RAG 공식 문서, Anthropic의 컨텍스트·하네스 자료, OpenAI의 요청 작성 자료를 참고한다. URL은 화면의 공식 참고 자료에 연결한다. 개별 도구의 내부 구현을 일반 RAG 도식과 동일하다고 단정하지 않는다. 가격·한도를 고정 수치로 가정하지 않는다.

AI의 새 응답, 무료 계정 전체 환경, 실제 수업 시간, 수강생 이해도 및 실제 절감 효과는 이번 웹 QA의 검증 범위가 아니다. 새 설명·요청·판정 예시는 강사 구성이다. 브라우저 기능·반응형 배치·원문 해시·저장 호환은 `docs/verification.md`에 별도로 기록한다.
