실습지원 요청 분리

s1 · 프로그램 적용

접속· 입력 보조가 필요한 학습자의 요청은 운영 메모로 기록한다. 지원 요청 유무는 채택· 참여· 만족도 계산 조건에 추가하지 않는다.

s2 · 예외·적용 한계

접속에 성공했다는 메모만으로 참여 여부 N을 Y로 바꾸지 않는다. 원본 참여 값 정정이 필요하면 담당자 확인 전 보류 의견만 남기며 본 실습 데이터는 보존한다.

s3 · 프로그램 보고 기록

지원요청 종류·처리상태·계산영향없음을 기록한다.

s4 · 접속 보조를 받은 신청자의 통계 처리

디지털기초 담당자가 “도움을 받아 로그인한 학생은 독립 참여자가 아니므로 빼자”는 의견을 냈다. 현재 기준의 참여 여부는 원본의 Y/N이며 지원 요청 유무를 제외 조건으로 추가하지 않는다. 한편 접속 지원 메모만 있고 원본 참여가 N인 경우 그 메모를 근거로 Y로 바꿔서도 안 된다. 지원 기록은 교육 운영을 개선하기 위한 자료이고, 본 실습 신청· 참여· 만족도 판정의 대체 자료가 아니다. 가상 사례 A는 ID 정상· 첫 기록· 참여 Y· 점수 4· 지원 요청 있음이다. 상위 기준에 따라 채택· 참여 1· 유효응답 1· 점수 4이며 지원 요청은 계산에 영향을 주지 않는다. 사례 B는 ID 정상· 참여 N· 지원 요청 있음이다. 채택· 참여 0· 응답 0이고, “지원받았으니 참석했다”는 추론을 하지 않는다. 사례 C는 참여 값이 도움으로 적혀 있다. Y/N 밖이므로 보류하며 의미가 비슷해 보인다는 이유로 변환하지 않는다.

s5 · 부서 검토 회신과 후속 업무

담당자는 지원 유형· 해결 상태· 추가 안내 필요를 별도 운영 표로 관리한다. 공개 실습에는 실제 학생의 장애· 건강· 개인 연락처 같은 정보가 필요하지 않다. 이 가상 지원 메모가 실제 서비스 접근성을 평가한 증거도 아니다. 보고 문장은 “가상 운영 사례에서 접속 지원 요청을 통계 조건과 분리했다”처럼 범위 안에서 쓴다. 추가 자료를 요구받으면 현재 입력에 있는 열과 없는 열을 명시한다.
