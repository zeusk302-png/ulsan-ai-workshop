O09 · UTF-8 CSV 입력 변환 장부

운영·검증 | v1.0 | 시행 2026-11-06 | 상태 current
범위: R01·R02 가상 교육사업 | 상위: B01

확장 입력

s1 · 수행 조건

선택 CSV는 UTF-8 BOM· 쉼표 구분이며 회차·ID를 텍스트로 유지한다. 숫자로 해석 가능한 만족도 문자열은 별도 숫자열로 변환한다.

s2 · 예외·실패 사례

CSV의 빈 문자열은 미응답이다. 자동 형식 추론으로 회차·ID의 앞자리나 문자 값을 잃지 않도록 원문 열을 보존한다.

s3 · 남길 증거

원문 문자 열/ 변환 값/ 변환 실패/ 판정 사유를 기록하고 먼저 R01만 본 실습과 대조한 뒤 R01~R10으로 확장한다.

s4 · CSV 문자인 숫자를 읽는 두 단계

확장 CSV에서 만족도 문자 열"3"은 원문을 보존한 채 숫자 3으로 해석해 유효 점수 조건을 검사한다. 빈 문자열은 0으로 변환하지 않고 미응답으로 남긴다. "좋음"은 숫자 변환 실패이고"6"은 변환 성공이지 만 점수 범위 오류다. 변환 실패와 범위 오류를 하나의 값 0으로 합치면 추적 정보가 사라진다. 회차와 ID는 숫자로 변환하지 않는다. 같은 ID라도 다른 회차는 별도 키다. 전체 10만 행을 한 번에 보고한 결과가 정확한지 확인하기 전에 R01 부분을 선택해 본 실습 1만행과 검 산한다. 지원 계정이 파일 크기를 감당하지 못하면 처리 한 회차와 남은 회차를 명시한다. 단순 TXT의 검색 결과를 전체 CSV 집계로 대신하지 않는다.

s5 · 판정표와 인수 조건

"3" | 숫자3·유효 "" | 미응답 "6" | 숫자6·불량 "2.5" | 숫자2.5·불량 "좋음" | 변환실패·불량 위 표는 해당 문서의 조건을 작은 사례로 검토하는 도구다. 원본 전체의 실제 처리 기록, 사용한 파일· 회차· 도구, 확인하지 못한 사항은 별도의 실행 장부로 남긴다.
