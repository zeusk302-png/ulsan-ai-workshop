파일 운영

s1 · 적용 조건

sources는 기준, data는 원본, templates는 양식, work는 중간 기록, output은 결과, checks는 검 산 기록이다. 원본과 기준은 덮어 쓰지 않는다. 회차가 다른 결과는 파일 이름으로 구분한다.

s2 · 예외·혼동 주의

폴더에 넣은 것만으로 웹 AI에 첨부되거나 RAG 소스가 되지 않는다. 실제 첨부· 읽기· 권한 상태를 확인한다. README를 읽은 행위는 파일 생성이나 코드 실행의 증거가 아니다.

s3 · 관찰·검증 기록

작업 일지에 입력 파일, 읽은 범위, 도구, 생성 파일, 처리 건수, 사람의 복사· 검토, 미확인 항목을 적는다. 외부 발송· 실제 개인 정보· 비밀 값은 이 가상 연습에 필요하지 않다.

s4 · 입력에서 출력까지 파일 인수 흐름

시작 전: 압축을 푼 실습 폴더를 확인하고 README와 기준 파일을 읽는다. 로컬 도구는 현재 작업 위치와 읽을 경로를 확인하며 웹 AI는 필요 파일을 직접 첨부한다. sources에 72개 문서가 있어도 외부 노트북에 자동 등록되는 것은 아니다. 첨부 목록과 도구가 보고한 실제 파일 목록이 일치하는지 확인한다. 입력 목록 예: 기준은 sources/operating-rules.txt와 report-guide.txt, 데이터는 data/round-01.xlsx, 양식은 templates/report-template.pptx다. 문서 조회로 만든 근거 표는 work에 두고 검토 상태를 적는다. 최종 XLSX/PPTX는 output에 회차별로 저장한다. checks에는 행수· 산식· 차트·PPT 대조 기록과 미확인 항목을 남긴다. 체크 목록 파일을 만든 것만으로 실제 검증이 실행되지는 않는다. 실패 처리: data 파일을 읽지 못 했는데 예시 summary를 대신 읽어 보고서를 만들면 기대 값을 복사한 결과일 뿐이다. 읽기 실패· 지원하지 않는 형식· 처리 중단은 도구 오류와 남은 범위를 구체적으로 표시한다. 일부 행만 처리했으면 전체 완료라고 말하지 않는다. 지원 도구가 없는 상황에서는 제 공 검 산 파일로 원리를 확인하는 대체 학습과 실제 처리 완료를 구분한다. 결과인 수: 생성 파일을 다운로드한 위치와 열어 본 프로그램을 적는다. 사람의 복사· 업로드· 수동 수 정도 일지에 남긴다. 실제 AI가 파일을 생성한 것인지 미리 제공된 예시를 받은 것인지 확인한다. 이 가상 연습은 외부 발송· 게시· 실기 관의 비밀 정보를 요구하지 않으며 파일 목록에 개인 정보나 인증 토큰을 넣을 필요가 없다.

s5 · 중단된 파일 생성 작업을 입력부터 복구하는 사례

파일 생성 AI가 긴 작업 도중 멈추고 대화창에 집계 표 일부만 남긴 상황을 가정한다. 담당자는 보이는 표를 곧바로 완성 엑셀로 간주하지 않았다. 실제 다운로드 파일이 있는지, 파일을 열 수 있는지, 정리와 근거 시트가 포함되어 있는지부터 확인했다. 실행 계획을 제시한 응답, 코드를 보여 준 응답, 일부 결과를 출력한 응답, 실제 파일을 생성한 응답은 각각 다른 상태다. 복구할 때에는 작업 폴더를 기준으로 현재 가진 파일을 정리한다. data의 원본은 보존하고 work에는 중간 장부를, output에는 검토할 산출물을, checks에는 대조 기록을 둔다. 파일명에는 회차를 넣어 이전 결과와 구분한다. 원본과 결과에 같은 이름을 쓰지 않아야 중단 후 어느 입력에서 다시 시작해야 하는지 알 수 있다. 예시 검산값 파일이 옆에 있더라도 그것을 새 원본처럼 읽어 처리했다고 기록하지 않는다. 웹 도구를 다시 열었다면 이전 대화의 첨부가 현재 대화에서도 읽히는지 확인한다. 로컬 도구를 바꾸었다면 같은 폴더를 열었는지와 지침 파일의 적용 범위를 확인한다. “앞에서 준 자료로 계속해”라는 말만으로 필요한 파일이 전달되었다고 가정하지 않는다. 요청에는 기준 문서, 대상 회차 원본, 근거표, 출력 경로를 다시 지정하고 읽을 수 없는 파일을 먼저 표시하게 한다. AI가 파일을 읽었다고 응답하면 실제 시트명과 열 구조, 처리 대상 행 수를 대조한다. 중간 장부가 남아 있다면 그 장부의 범위를 확인한 후 재사용 여부를 정한다. 첫 몇 행만 처리한 표와 전체 판정 장부는 다르다. 처리 범위가 불명확하거나 적용 기준이 다른 중간 결과라면 그것을 이어 붙여 완료로 만들지 않고 원본에서 다시 실행한다. 재실행한 결과는 원본 행 수와 채택·제외·보류의 합, 지표의 분자·분모, 프로그램 합계로 확인한다. 대표 오류 행도 원본과 대조해 단순 합계 일치 뒤에 잘못된 판정이 숨지 않았는지 살핀다. 산출물을 내려받은 뒤 사람이 한 복사와 업로드도 기록한다. 파일이 생성되었다고 외부 제출이나 발송까지 자동 완료된 것은 아니다. 이 교육 실습은 외부 발송을 요구하지 않으므로 결과 확인을 넘어 임의로 게시하거나 공유할 필요가 없다. 작업 기록에는 실제 입력, 적용 기준, 생성된 파일 경로, 직접 연 파일, 확인한 계산과 아직 확인하지 못한 내용을 구분한다. 실패 복구가 끝났다는 뜻은 대화가 다시 이어졌다는 것이 아니라, 보존한 입력에서 검토 가능한 산출물까지의 연결을 다시 확보했다는 뜻이다. 복구 과정에서 임시 결과가 여러 개 생기면 검토한 결과의 위치를 한 곳에 명시한다. 파일명에 final을 반복해 붙이는 대신 회차와 작업 내용을 구별하고, 작업 기록에서 현재 검토 대상 파일을 지정한다. 다른 사람이 오래된 파일을 열어 숫자를 옮겼다면 새 결과를 만든 사실만으로 보고가 갱신되지 않는다. 최종 전달 단계에서 사용한 파일명과 집계 회차까지 확인해 입력부터 전달까지의 연결을 닫는다.
