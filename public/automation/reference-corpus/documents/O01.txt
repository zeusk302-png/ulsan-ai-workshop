s1 수행 조건
업로드 전 파일 명· 확장자· 회차· 바이트 수를 목록으로 적는다. round-01.xlsx를 첨부하려다 예시 summary를 첨부한 경우 원본 처리 요청을 중단하고 바로잡는다.

s2 예외·실패 사례
첨부 아이콘의 파일 명과 도구가 보고한 시트· 열을 대조한다. 첨부 완료 표시가 있어도 읽기 실패가 나면 처리 완료로 기록하지 않는다.

s3 남길 증거
첨부목록/읽기성공/미읽음/대체경로를 기록한다.

s4 첨부 파일이 바뀐 실패를 발견한 인수회의
담당자는 round-01.xlsx 대신 examples의 요약 파일을 첨부했다. AI는 원본 행 수 10,000을 답했지만 실제 읽은 파일은 이미 집계된 예시였다. 검토자는 숫자가 맞는지를 확인하기 전에 첨부 목록과 실제 시트 구조를 비교했다. 요약 시트만 보이는 파일에서는 개별 행 판정을 재현할 수 없으므로 전체 처리 완료 주장을 취소했다.

복구 순서: 잘못 첨부한 예시를 원본 처리의 근거에서 빼고 올바른 파일을 첨부한다. 사용 가능 도구로 시트· 열· 행수를 다시 읽고 전체 처리를 시작한다. 이전 결과는 실패 사례로 남겨 어떤 파일을 읽었는지 기록한다. 파일 명 하나가 맞아도 복사 본 내용이 다를 수 있으므로 도구의 실제 읽기 확인이 필요하다.

s5 판정표와 인수 조건
원본 미첨부 | 전체 처리 요청 보류
파일 첨부· 읽기 실패 | 지원 상태 확인
원본 첨부· 전체 읽기 확인 | 정리 진행
예시 파일만 열기 | 원리 학습으로 표시
위 표는 해당 문서의 조건을 작은 사례로 검토하는 도구다. 원본 전체의 실제 처리 기록, 사용한 파일· 회차· 도구, 확인하지 못한 사항은 별도의 실행 장부로 남긴다.
