B08 · 검산 XLSX 구조와 계산 책임

핵심 안내 | v1.0 | 시행 2026-11-06 | 상태 current
범위: R01·R02 가상 교육사업 | 상위: B01

엑셀

s1 · 적용 조건

원본/ 정리/ 요약/ 근거 시트를 유지한다. 파일 계산 도구가 전체 행의 중복 키와 판정을 값으로 만들고 Excel에는 단순 행별 기여 수식과 SUM·COUNTIF 같은 요약 수식을 남긴다.

s2 · 예외·혼동 주의

매 행의 앞선 모든 행을 다시 찾는 확장 COUNTIF 중복 판정은 본 실습에 사용하지 않는다. 10,000 행과 헤더 1 행이면 데이터 끝은 10,001 행이다. 새 행을 넣으면 정리· 집계· 차트 범위를 함께 확인한다.

s3 · 관찰·검증 기록

저장 파일을 열어 수식 입력 줄과 표시 값을 대조한다. 수식 문자열의 존재, 저장된 표시 값, 실제 재계산 실행은 별개다. 계산이 안 되면 재계산 가능한 프로그램에서 열고 저장하며 미수행은 기록한다.

s4 · 값·수식·재계산·표시값의 네 가지 상태

파일 구조 의뢰: 정리 시트에서 중복 여부가 이미 판정된 XLSX를 받았다. 요약의 숫자만 맞추는 대신 행별 참여 기여· 응답 기여· 점수 기여와 요약합계를 연결한다. 정리 상태 값은 파일 계산 도구의 판정 결과이고, 기여 수식은 그 상태를 지표에 반영하는 연결이다. 둘을 같은 종류의 연산으로 여기지 않아야 새 입력에서 무엇을 재실행할지 알 수 있다. 참조 예: 2 행이 채택 +Y· 점수 4이면 참여 기여 1, 응답기여 1, 점수기여 4다. 3 행이 채택 +Y· 공란이면 참여 기여 1, 응답기여 0, 점수기여 0이다. 4 행이 후속 중복이면 원문 점수가 5여도 세기여는 0이다. 요약은 전체 기여를 합하고 참여율 =참여 합/ 채택수, 만족도 =점수 합/ 응답 합으로 계산한다. 수식의 구체열주소는 실제 파일에서 확인해야하며 다른 예제의 주소를 맹목적으로 복사하지 않는다. 저장 전후: 생성 라이브러리가 수식 문자열을 저장했으나 계산을 수행하지 않았다면 뷰어는 결과를 비워 보이거나 이전 저장 값을 보여 줄 수 있다. 따라서 수식 입력 줄의 내용과 표시 숫자를 동시에 확인하고 재계산이 실제 수행된 환경을 기록한다. “수식이 들어 있다”와 “계산 값을 검증했다”는 다른 완료 조건이다. 코드 출력을 보았다는 사실도 Excel 프로그램에서 열었다는 뜻이 아니다. 범위 변화: 본 실습은 데이터 2~10001 행이다. 별도 복사 파일에 새 행을 추가하는 자습에서는 마지막 행을 포함하도록 원본 읽기· 정리행· 집계 수식· 차트 원본을 모두 검토한다. 합계셀 하나를 넓혔다고 다른 부분이 자동 갱신됐다고 가정하지 않는다. 새 입력의 값이 실제 기여 열과 차트에 도달하는지 추적하는 것이 재실행 검사의 핵심이다.

s5 · 수식이 있어도 갱신되지 않는 엑셀의 복구 사례

새 회차 결과 파일을 열었는데 요약 숫자가 이전과 같아 담당자가 재사용 성공으로 보고하려 했다. 검토자는 표시 숫자만으로 재계산 여부를 판단할 수 없다고 보았다. 먼저 현재 입력 파일과 회차를 확인하고, 정리 시트의 전체 행 수, 포함 플래그, 집계 수식의 범위를 차례로 살폈다. 파일에 수식 문자열이 들어 있다는 사실, 계산 결과가 저장되어 있다는 사실, 현재 입력으로 다시 계산했다는 사실은 서로 다르다. 원본·정리·요약·근거 시트를 나누면 이 차이를 확인하기 쉽다. 원본 시트는 읽은 값을 보존하고, 정리 시트는 판정과 기여를 추가한다. 요약 시트는 정리 결과를 합산하며 근거 시트는 적용 문서와 조항을 보관한다. 파이썬 등 파일 처리 도구가 전 행의 중복과 판정을 만든 경우에도, 엑셀에서 대조할 수 있도록 전체 처리 범위와 플래그의 의미를 남긴다. 수만 행에 누적 중복 수식을 반복하는 방식과 사전에 판정한 결과를 간단히 합산하는 방식은 계산 부담도 다를 수 있다. 웹의 별도 8행 원리 모형에서는 헤더를 포함한 계산 범위가 2행부터 9행까지다. 신청 채택 수, 참여 플래그, 유효 응답 플래그, 점수 기여를 이 범위에서 합하면 채택 5, 참여 4, 응답 2, 점수합 8이 나온다. 같은 회차의 유효 참여 응답 한 행을 추가한 비교 모형에서는 끝행도 10행으로 늘려야 한다. 자료는 늘었는데 집계 수식이 9행에서 끝나면 마지막 행의 기여가 빠진다. 이 예시는 실제 본 실습 검산 파일의 셀 주소를 대신하지 않는다. 복구 요청에는 “평균을 고쳐 달라”보다 “실제 마지막 데이터 행을 확인하고 원본·정리·요약이 같은 범위를 처리하는지 대조하라”는 조건을 넣는다. 수식이 잘못되었다면 원본을 보존하고 새 파일에서 범위를 수정한다. 저장 후에는 사용하는 편집기로 다시 열어 수식, 오류 표시, 숫자와 차트를 확인한다. 생성 환경에서 재계산하지 못했다면 가능한 검사와 못 한 검사를 나누어 기록한다. 수식의 존재만 확인한 상태를 실제 재계산 완료라고 쓰지 않는다. 표시 형식도 따로 확인한다. 만족도 4라는 계산값을 4.00으로 보여 주는 것은 값의 변경이 아니라 표시 자릿수의 선택이다. 본 실습의 회차별 만족도는 표시가 같아 보일 수 있으므로 점수합과 응답 수까지 비교한다. 화면에 보이는 소수 둘째 자리만 맞추기 위해 원자료나 계산값을 반올림해서 덮어쓰지 않는다. 수정한 범위, 다시 연 프로그램, 대조한 셀, 남은 미확인 상태를 작업 기록에 적으면 다른 사람이 파일을 이어받아도 무엇을 믿을 수 있는지 알 수 있다. 차트를 검토할 때에도 수식 범위를 함께 본다. 표의 마지막 행이 갱신되었는데 차트가 이전 고정 영역을 참조하면 셀 값은 맞고 막대만 낡은 상태가 생긴다. 집계 셀과 차트의 원본 범위, PPT에 사용한 그림의 생성 시점을 연결해 확인한다. 숫자가 달라 보이는 위치를 곧바로 계산 오류로 단정하지 않고 실제로 참조한 데이터가 같은지부터 확인하면 수정할 범위를 좁힐 수 있다.
