P03 | 공식 API 39개 상가 항목과 실제 CSV 39열의 대응
성격: 공식 Swagger 설명 그대로 / CSV 열 대응과 적용 주석은 강사 작성
버전: Swagger 1.0.0 / 확보 2026-11-06
출처ID: sbiz-field-dictionary, sbiz-api-guide

s1 대응표의 출처와 한계
공식 API 페이지에 포함된 Swagger의 storeOne 응답 항목을 사용했다. 응답 속성 44개에서 columns·description·resultCode·resultMsg·stdrYm이라는 응답 메타 정보 5개를 제외하면 상가 항목이 39개다. 이 수는 실제 울산 두 CSV의 39개 헤더와 독립적으로 대조했다. 아래 대응 표는 API 순서를 CSV 순서라고 가정해 자동 연결한 것이 아니라 영문 항목과 한글 CSV 열을 명시적으로 대응한 강사 작성 표다. API 타입은 원문 string으로 보존하며 좌표를 숫자로 해석하는 분석 처리는 원 문 타입 정의의 변경이 아니다. 이용 허락 범위 제한 없음(공식 포털 표시). 첨부 HWP만의 별도 이용 조건은 확인하지 못 했으므로 제공 기관· 원본 출처와 추출 사실을 유지한다.

s3 울산 구·군 코드 - 공식 가이드 부록에서 확인
출처 위치: 공식 가이드의 참조·행정구역 조회→시군구. 아래 코드를 새로 발명한 것이 아니다.
시도 31 울산광역시 | 시군구 31110 중구
시도 31 울산광역시 | 시군구 31140 남구

시도 31 울산광역시 | 시군구 31710 울주군
[강사 적용 주석] 시 군 구 코드를 텍스트로 사용해 이름과 함께 집계한다. 행정동과 법정동을 같은 단위로 결합하지 않는다. 코드 북· 주소의 관측 시점 차이는 원본과 함께 남긴다.

s4 [강사 주석] 공식 좌표 설명 충돌
공식 Swagger는 lon과 lat 두 항목 설명에 모두 “WGS84 기준 위도 좌표 값”이라고 쓴다. 원문을 경도로 고쳐 인용하지 않는다. 실제 CSV 헤더는 경도·위도로 분리돼 있고 울산 자료의 경도는 약 129, 위도는 약 35이다. 가이드의 경도/ 위도 요청·응답 문맥과 실제 헤더·값 범위를 함께 대조해 경도 열은 가로 축, 위도 열은 세로 축으로 사용한다. 이 판단은 공식 설명의 불일치에 대한 강사 적용 해설이지 두 설명이 원래부터 일치했다는 주장이 아니다. 좌표가 그럴 듯한 범위라고 개별 위치 정확성을 현장 검증한 것은 아니다.
